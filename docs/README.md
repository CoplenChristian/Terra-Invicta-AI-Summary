### Small follow-ups, unassigned

- **`tests/powershell_common.test.js` reports six green passes without running
  anything.** All six spawn `pwsh` and `return` early on `probe.error?.code ===
  'ENOENT'`, so on a machine with no PowerShell 7 they pass in ~2.5 ms each having
  executed no PowerShell at all — the suite cannot tell "the module is correct"
  from "the module was never loaded". Measured 2026-08-22: `pwsh` is **not on this
  machine's PATH**; Windows PowerShell 5.1 is (`C:\WINDOWS\System32\WindowsPowerShell\v1.0\powershell.exe`),
  and the test never tries it. This matters more since the repo-structure move,
  because `TerraInvicta.Common.psm1` is now the one dependency crossing the
  tool/dashboard boundary. A skip would at least be honest; falling back to
  `powershell.exe` would be better. `tests/repoStructure.test.js` guards the
  module's *path* textually, which is unaffected, but nothing executes its code.
- **Five config keys the dashboard validates and never reads.** `paths.csvSubDir`,
  `shipInfoSubDir`, `againSaveSubDir`, `summarySubDir` and `snippetPackSubDir` are
  **`required`** in `config/config.schema.json` and defaulted in `config/defaults.json`,
  but the only consumers are the PowerShell/Python scripts now in
  `md-generation-reports/`. `paths.workDir` has no Node reader at all —
  `server/config.js` migrates and validates it, and nothing consumes it. They were
  deliberately left in place by the repo-structure move because relocating them
  touches `tests/config.test.js` and `tests/powershell_common.test.js`, which is a
  change, not a move.
- **`md-generation-reports/export_factions.py` opens `config.json` with no guard.**
  Every other script in that directory tolerates a missing `config.json` because
  `Get-TIConfig` falls back to `config/defaults.json`; the Python exporter does
  `CONFIG_PATH.open("r")` unconditionally and raises `FileNotFoundError`. It also
  reads only the flat legacy keys (`WorkDir`, `SavePath`, `AgainSaveSubDir`), so a
  purely nested `config.json` silently gives it the wrong output directory rather
  than an error. Pre-existing; not touched by the move.
- **Four dead browser scripts at the repository root.** `test_browser.js`,
  `test_browser_councilors.js`, `test_browser_v2.js` and `test_new_intel_endpoints.js`
  (all 2026-08-19) are superseded by `scripts/verify_*.js`. Nothing runs them. They
  were left where they are because `docs/archive/strategic-intelligence-suite/`
  cites them by root path, and because moving them into `scripts/` would add four
  modules to `docs/code-index.md` — both out of scope for a structural move.
- **`md-generation-reports/Ship_Info/generate_hab_module_tables.ps1.bak`** is a
  tracked editor backup of a script that still exists two directories up. Moved
  as-is rather than deleted, because deleting tracked files is not a move.
- **`res.sendFile` refuses to serve the shell from a dot-directory.** `server/index.js`
  passes an absolute path to `res.sendFile`, and `send` defaults to `dotfiles: 'ignore'`,
  so `/` and `/v2/` return 404 for any checkout living under a path segment that starts
  with a dot — an agent worktree in `.claude/worktrees/`, for instance. The API routes and
  `express.static` are unaffected, so it presents as a blank dashboard rather than an
  error. `tests/cssComputedStyle.test.js` fails there for the same reason.
- **A worktree has no `config.json`.** It is gitignored, so every save-backed test errors in
  a fresh agent worktree until it is copied across from the main checkout. Harmless once
  known, but it presents as a wall of failures unrelated to the change under test.
- **Three more confident defaults survive in `server/commentary/simulation.js`,** all latent
  on the live save and none of them fixed when the `ownRating = 5000` baseline was. An alien
  fleet with no readable `armorMedian` scores 10 and one with no `shipsCount` scores 1
  (`buildPlayerOpponentTiers`); an omniscient design population with no readable CVs falls
  back to p10/p50/p90 of 3250 / 20330 / 70100 (`buildOmniscientOpponentTiers`); and
  `rebuildClock` reports `available: true` with `baseConstructionTimeDays || 60` and
  `queuedCount || 2`, so an unread build time becomes a specific throughput. Measured
  2026-08-22 on `ExitSave.gz`: 0 of 57 alien fleets miss either field, every observer design
  carries a numeric CV, and `Monitor.baseConstructionTimeDays` reads 120 — so all four fire
  only on a save this one does not exercise. Same class, same file, left out of scope.
- **`buildPlayerOpponentTiers` computes `fleetSizes` and never uses it**
  (`server/commentary/simulation.js`). Dead since the tiers were rewritten to key off armour
  medians. Harmless, but it is the only place `shipsCount` is read in that function, so it
  reads as though fleet size were an input to the opponent rating when it is not.

## Archive

`archive/` holds finished plans, shipped specs and completed reviews. They are kept because
**source comments cite them** — they carry the reasoning behind decisions in the code, and
several record a model that was tried and rejected, which is worth as much as the one that
shipped.

Notable: `archive/directive-rule-engine-plan.md` is the v1 engine, superseded by
`archive/directive-engine-v2*.md`. `archive/strategic-intelligence-suite/` holds earlier
reviews and still cites four dead browser scripts by their repository-root paths.
`archive/repo-structure-spec.md` records the 2026-08-21 measurement of the root; three of
its figures were wrong and the Shipped row above says which.

## Conventions

Specs here record **what was measured**, not what was assumed. Where a model was rejected,
the rejection and its evidence stay in the document rather than being deleted —
`research-advisor-spec.md` keeps a superseded armour derivation for exactly that reason,
and `campaign-settings-spec.md` keeps two discarded measurement attempts so they are not
repeated.

When archiving, update the citing source comments in the same commit; the paths are
load-bearing.
